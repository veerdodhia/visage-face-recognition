Face recognition that runs on your own devices.

Visage recognises the people you have enrolled from a webcam or a photo, on the machine in front of them. No biometric image leaves the building: the browser turns each face into 128 numbers and matches those, and keeps the numbers, never the photo.

        How it works

        Four networks run in sequence on every frame. Each one hands a smaller, more precise piece of data to the next.

        1. Detect

          The Tiny Face Detector, a small convolutional network, scans the frame and returns a bounding box and a confidence score for every face it finds.

        2. Align

          A landmark network places 68 points on eyes, brows, nose, mouth and jaw. Those points normalise the crop for tilt and position, so the next step always sees a face in the same pose.

        3. Embed

          A ResNet-34 style network turns the aligned face into a 128-dimensional descriptor. Faces of the same person land close together in that space; different people land far apart.

        4. Match

          The live descriptor is compared with every enrolled descriptor using Euclidean distance. The closest one wins if its distance is below the threshold (0.55 by default); otherwise the face is Unknown.

        Where it fits in an organisation

        Anywhere a person has to be recognised at a fixed point: a door, a desk, a counter, an onboarding screen. The device already there does the work.

        Attendance
        Enrol staff or students once. A laptop or tablet at the entrance recognises each person as they arrive and records a timestamp, with no card to forget and no register to sign.
        Access control
        A lab, server room or office door checks a face against a short enrolled list and refuses everyone else. The list lives on the device guarding the door, not in a cloud account.
        KYC and identity verification
        Compare a live face with the photo on an ID document during onboarding. The distance between the two descriptors is the evidence, and it is computed on the branch device, so the customer's face is never uploaded.
        Visitor management
        Enrol a visitor at reception for the day. Front-desk and floor devices recognise them on return without re-checking ID, and Remove clears them when the visit ends.

        No biometric image leaves the building

        Privacy here is how the system is built, not a policy. Each point below is something a security or compliance review can verify in the code.

        • Everything runs on the device in front of the person. The models are loaded from the site folder and executed by TensorFlow.js in the browser. There is no server to send frames to, and nothing for you to host.
        • Descriptors, never photos. Enrolling a person stores 128 numbers. The image is discarded as soon as those numbers are computed, and a descriptor cannot be turned back into a face.
        • Stored on that device only. Enrolments live in the browser's localStorage. Nothing syncs anywhere on its own.
        • Removable, any time. Every enrolled person has a Remove button, so a visitor's data ends with the visit.

        What it is made of

        Recognitionface-api.js, running on TensorFlow.js in the browser
        ModelsTiny Face Detector, 68-point tiny landmark net, ResNet-34 style recognition net, expression net. Weight files are vendored in models/.
        SitePlain HTML, CSS and JavaScript. No build step, no framework, no backend.
        StorageBrowser localStorage, descriptors only
        Runs fromAny static server: VS Code Live Server or python -m http.server. Works offline once the folder is on disk.
